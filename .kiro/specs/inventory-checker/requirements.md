# 在庫チェックアプリ — 要件定義

## 概要

カメラで撮影した画像をAIで判定し、家庭内の在庫（食品・日用品）を管理するPWAアプリ。
判定結果から在庫リストを更新し、不足品から買い物リストを生成する。

- **直接的な目的**: 開発のサンドボックス（カメラAPI、画像認識、Strategy Pattern等の技術検証）
- **二次目的**: 買い物リストの作成・在庫管理

## ユーザー

- 2人（自分たち）のみ
- 端末間でデータ共有する

## 機能要件

### FR-1: カメラ撮影

- スマートフォンのカメラで写真を撮影できる
- ギャラリーから既存画像を選択することもできる
- 撮影した画像はブラウザのメモリ上で処理し、サーバーには送信しない（ローカルAI使用時）

### FR-2: AI判定（物体認識）

- 撮影画像から物品を自動判定する
- 判定エンジンは差し替え可能な設計とする（Strategy Pattern）
  - **第1候補（ローカル）**: TensorFlow.js + COCO-SSD等のモデル
  - **第2候補（クラウド）**: Gemini API無料枠 / Cloud Vision API無料枠
- 判定結果は品名のリストとして返す
- クラウド使用時は画像データの送信について明示する

### FR-3: 在庫リスト管理

- 判定結果から在庫アイテムを追加できる
- 手動でアイテムを追加・編集・削除できる
- 各アイテムの属性:
  - 品名
  - カテゴリ（食品/日用品/その他）
  - 状態（あり/残りわずか/なし）
  - 最終確認日
- 在庫状態を手動で変更できる

### FR-4: 買い物リスト生成

- 「なし」「残りわずか」の在庫アイテムから買い物リストを自動生成できる
- 手動で買い物リストにアイテムを追加・削除できる
- 購入済みチェックが付けられる
- 購入済みにしたアイテムの在庫状態を「あり」に更新する

### FR-5: データ同期

- Firestoreにデータを保存し、端末間でリアルタイム同期する
- Firebase Authentication（Googleログイン）で認証する
- 既存kaji-appと同じFirebaseプロジェクトを使用する

## 非機能要件

### NFR-1: セキュリティ・プライバシー

- ローカルAI使用時、画像はブラウザ内で処理して即破棄する
- クラウドAI使用時、送信するデータを最小限にし、ユーザーに通知する
- 個人情報はサーバーに保存しない

### NFR-2: パフォーマンス

- AI判定は5秒以内にレスポンスを返す（目標）
- オフラインでも在庫リスト・買い物リストの閲覧が可能

### NFR-3: 対応環境

- モバイルファースト（iOS Safari / Android Chrome）
- PWA対応（ホーム画面追加、オフライン閲覧）
- PCブラウザでも動作する

### NFR-4: コスト

- 無料枠内で運用する
- ローカルAIを優先し、クラウドは無料枠の範囲内で使用する

### NFR-5: 拡張性

- 将来的にkaji-appとハブ型UIで統合する前提で設計する
- 同じFirebaseプロジェクト・同じ認証を使い、統合を容易にする
- AI判定エンジンの差し替えが容易な設計にする

## 対象外（スコープ外）

- レシート読み取り（OCR）— 将来検討
- 賞味期限管理 — 将来検討
- 自動発注・EC連携
- 複数世帯対応

## 技術スタック

| 用途 | 技術 |
|------|------|
| フロントエンド | HTML + CSS + JavaScript（素） |
| AI判定（ローカル） | TensorFlow.js + COCO-SSD / MobileNet |
| AI判定（クラウド） | Gemini API / Cloud Vision API（無料枠）|
| 認証 | Firebase Authentication（Googleログイン） |
| データベース | Firestore |
| ホスティング | GitHub Pages |
| PWA | Service Worker + manifest.json |
